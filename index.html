Coherence across Time, for movies longer than any generation window.

A long movie has to be generated window by window. CaT-Movie writes one storyboard before the first frame, then uses it twice: as self-contained text for every shot, and as an index into the frames it has already generated. The window renderer borrows identity from those frames and takes state and framing from the text.

The trade-off

Long movies are stitched from windows. What crosses the seam decides what breaks.

A diffusion pass renders a limited duration, so a story of a minute is generated as consecutive windows of shots. Events leave consequences and characters return with changed attributes long after the window that introduced them.

Joint generators coordinate cuts inside a window and lose identity beyond it. Memory-augmented generators carry earlier frames forward, but a recalled frame bundles identity with the camera setup and story state of its shot. Per-shot pipelines cut cleanly and forget. Method

One storyboard writes the words and points at the pictures.

A global story planner expands the request into a structured storyboard. Deterministic code maintains it across shots, compiles a self-contained prompt for every shot and indexes reference frames from the generated history. A local window renderer then denoises each window of shots jointly.

01 · Request

Any granularity in, the same storyboard format out.

Requests range from a one-sentence synopsis to a numbered shot list. One prompt tells the planner to preserve stated facts, infer implied presence and event outcomes, and complete open details such as postures. It writes a composition only when the request implies an opening layout.

The planner keeps every requested event and 90–98% of requested outcomes, and invents at most 0.07 items per plan.
02 · Storyboard

An entity registry and a plan for every shot.

The registry gives each recurring character, object and location a fixed identifier and an identity description, plus a default attire per character. Each shot records location, camera, present entities with posture, held items and attire, the action, and within-shot changes with visible final values.

Code copies back what a shot list states, carries attire from its latest recorded change, fills unstated held items from the previous shot and compiles one self-contained prompt per shot.

With code maintenance, a weaker 9B planner's post-change attire accuracy rises from 33.6% to 47.7%.
03 · Windows

Shots are packed into generation passes.

Code scales shot durations to the target length and packs consecutive shots greedily into windows under the cap; a longer shot fills a window alone. Each pass is denoised jointly, so the cuts inside it are coordinated.

Under the 7 s cap, 617 of 675 entity returns in our test storyboards cross a window boundary.
04 · Recall

The storyboard decides which generated frames come back.

Recall is a deterministic query on the storyboard, not visual similarity. Each entity keeps its clearest anchor view while its planned appearance holds: views after the latest attire or state change first, then fewer other characters, then a legible shot size, then the earliest shot.

A shot reads only the recalled frames that share one of its present entities, so it cannot borrow framing from a frame that shows other people. Pick a pass to see what it recalls.

Recalling the latest shots instead loses 9.3 points of character and 9.5 of scene consistency.
05 · Render

Each shot reads itself, its neighbours' first frames, and its own references.

The renderer is Wan2.2-TI2V-5B fine-tuned without new parameters. Shot-wise cross-attention lets each shot attend only to its own prompt. Reference-routed sparse self-attention lets it attend to its own tokens, the first latent frame of every co-generated shot, and its routed recalled frames, which sit at temporal positions before its first frame.

Training pairs whole shots with frames from other shots of the same scene, often under another camera setup, so copying their framing raises the loss. Trained for 3,000 steps on 8 A100 GPUs.

Without routing, cut execution drops from 0.970 to 0.869 where routing would hide frames of absent characters; 32 of the 34 failures copy a framing.

CaT-MBench

Consistency counts only when the planned cut happens.

Feature-similarity metrics reward a video that repeats the previous framing. CaT-MBench asks a judge whether each registered entity is the same individual when it returns, and counts that check only across cuts that open the planned new camera setup.

A cut counts as executed when TransNetV2 finds it within 0.5 s and the judge sees a new place, shot size, angle or cast. The same test gates every consistency and persistence check between shots the storyboard makes different. A check behind a failed gate fails and stays in the average.

Film storyboard dataset

Real films, annotated in the same schema the planner writes.

No open multi-shot dataset pairs entity registries with per-shot states and camera setups. We split films into shots, grouped consecutive shots of one scene into blocks of up to twelve, and had Qwen3.7-Flash annotate each block in one pass, which keeps identifiers consistent across its shots.

Aesthetic, technical and annotation checks drop single shots rather than every window that contains one, which retains 28.1% more usable shots.
